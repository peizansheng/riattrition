## What this package does

`riattrition` is an R package for **randomization inference in randomized experiments with sample attrition** (missing outcomes). It builds valid p-values and confidence intervals for Fisher sharp null hypotheses `H_0: tau = c` by imputing worst-case potential outcomes for missing/attrited units, computing a rank-based test statistic, and comparing it against a randomization null distribution.

## Architecture

The package implements two parallel procedures across two source files. Both share the rank/null-distribution machinery defined in the first file.

**Public API is intentionally small — only 4 exported functions:** `pval_sharp()`, `ci_sharp()`, `pval_sharp_twostep()`, `ci_sharp_twostep()` (see `NAMESPACE`). Everything else in `R/` (all the helpers named below — `null_dist`, `assign_CRE`, `test_stat`, `rank_score`, `pval_sharp_composite`, `pval_sharp_naive`, `ci_sharp_greater`, the `*_twostep` workers, `lci`/`uci`/`exactci`, `psi`, …) is an **internal helper** marked `@keywords internal`/`@noRd`, with no man page. When adding a function, default to internal unless it is genuinely meant for end users.

### `R/0_function_sharp_null.R` — single-step procedure

Shared building blocks (used by **both** files):
- `rank_score()` — Wilcoxon or Stephenson scores for `n` ordered units.
- `test_stat()` — the observed rank-based statistic, dispatched by `class`.
- `null_dist()` / `assign_CRE()` — Monte Carlo randomization null distribution via `nperm` random treatment assignments.

Main entry points `pval_sharp()` / `ci_sharp()` dispatch on the `missing` mechanism:
- `general`, `mp`, `mn` → `pval_sharp_composite()`: imputes a worst-case **composite** control potential outcome using bound triple `(b00, b01, b10)` (set per mechanism inside `pval_sharp`), then compares against the full `n choose n1` null.
- `sharp`, `random` → `pval_sharp_naive()`: drops missing units and runs an ordinary randomization test on the `n11 + n01` observed units (`n11 + n01 choose n11` null).

`ci_sharp()` inverts the test: it root-finds (`stats::uniroot`) the value of `c` where `pval_sharp(c) = alpha`. The upper bound is obtained by negating `Y` and reusing the lower-bound routine (`ci_sharp_greater`).

### `R/0_function_sharp_null_twostep.R` — two-step procedure

`pval_sharp_twostep()` / `ci_sharp_twostep()` implement a less conservative, two-step approach (only for `general`, `mp`, `mn`). Each two-step p-value is the randomization p-value **plus `beta`**, where `beta ∈ [0, alpha]` is the error budget spent in Step 1.

- **Step 1** builds a confidence interval for a hypergeometric parameter (the unknown count of always-/never-observed units) at level `1 - beta`. The fast path uses `ExactCIone::WhyperCI_M`; `lci()`/`uci()`/`exactci()` are slower exact-interval alternatives kept in the file (see the commented "Approach 2/3" blocks).
- **Step 2** uses that interval to restrict the worst-case imputation, then evaluates the `MWU+`/`MWU-` statistic.
- `pval_sharp_twostep()` dispatches to `pval_sharp_g_twostep()` (general), `pval_sharp_mp_twostep()` (monotone positive), or `pval_sharp_mn_twostep()` (monotone negative). Each is a full dedicated implementation — for `mn`, the "mirror `mp` by symmetry (negate `Y`, flip `Z`)" shortcut exists only as a commented-out alternative, so edit `pval_sharp_mn_twostep()` directly.

### Test statistic classes (the `class` / `method.list` axis)

Orthogonal to the missing mechanism, the statistic is chosen by `class`:
- `class = "RS"` (rank-sum): `method.list = list(name = "Wilcoxon")` or `list(name = "Stephenson", s = ...)`.
- `class = "MWU+"` / `"MWU-"` (generalized Mann-Whitney U): `method.list = list(name = "Wilcoxon")` or `list(name = "Polynomial", s = ...)`.

The two-step functions always use `MWU+`/`MWU-` internally.

## Testing notes

`tests/testthat/test-pval_sharp.R` asserts **exact numeric p-values** (e.g. `expect_equal(p_value_g, 0.7241)`). These depend on `set.seed(1)` and `nperm = 10^4`, i.e. the exact RNG stream and permutation logic. Any change to `assign_CRE()`, `null_dist()`, the seeding, or the default `nperm` will change these values and break the tests — update the expected numbers deliberately, not reflexively. (These literals also assume R ≥ 3.6 `sample()` semantics, even though `DESCRIPTION` declares `Depends: R (>= 3.5)`.)

## Known edge cases / gotchas

- **Two-step boundary indexing (guard already in place — do not remove).** In `pval_sharp_mp_twostep()` and `pval_sharp_mn_twostep()`, the worst-case imputation selects the "remaining observed" units with `(mlbar + 1):n11` (resp. `(mlbar + 1):n01`). When `mlbar == n11` (resp. `n01`) — reachable when an entire treatment arm's outcomes are all missing (`n01 == 0` or `n11 == 0`) — `(mlbar + 1):n11` would become the **descending** sequence `c(n11 + 1, n11)` instead of empty, erroring with `NAs are not allowed in subscripted assignments`. The code already guards this: `seq_len(mlbar)` for the `Inf`/`-Inf` block and `if (mlbar < n11)` / `if (mlbar < n01)` around the "remaining observed" block (`pval_sharp_mp_twostep()` ~L409-410, `pval_sharp_mn_twostep()` ~L487-490). Keep both guards if you touch this code — a naive "simplification" back to a bare `(mlbar + 1):n11` reintroduces the bug.
